# L2 · 仓库内端口标记规范

> 目的：让**每个平台版工具仓库自己就能说清**"我的端口是多少、谁分配的、改之前该看哪儿"。
> 登记表（tools-center/docs/ports.md）是中央真源，本规范是它在各仓库里的落地形式。

---

## 一、声明文件加 `_portNote` 字段

### 为什么安全（先论证，再动手）

JSON 不支持注释，但 tools-center 平台对未知字段是**完全静默忽略**的，已核实三处：

| 环节 | 代码位置 | 行为 |
|---|---|---|
| 解析 | `lib/core/manifest.js` → `normalizeManifest()` | 显式列举字段构造 `m` 对象，未列举的字段（含 `_portNote`）不进入内部视图，**不报错** |
| 校验 | `lib/core/registry.js` → `validate()` | 只校验 id/name/cmd/port/health/runtime/capabilities，**不校验未知字段** |
| 写回 | `lib/core/registry.js` → `updateToolMeta()` | `Object.assign(spec, n)` 只覆盖白名单字段，`spec` 原有 key（含 `_portNote`）原样保留后 `JSON.stringify` 写回 |

拖拽排序改分组走的是同一条 `updateToolMeta` 链路，所以 `_portNote` 也不会被拖拽操作抹掉。

### 规范

在 `manifest.json` 和 `tool.json` 的**顶层**加一个 `_portNote` 字段：

```json
{
  "id": "clipboard",
  "name": "剪贴板",
  "_portNote": "端口 8130 由 tools-center 统一分配，改动前查 tools-center/docs/ports.md 登记表；改端口必须同步 cmd 数组与 port 字段",
  "runtime": "node",
  "capabilities": ["storage"],
  "entry": "server.mjs",
  "port": 8130,
  "health": "/health"
}
```

约定：
- 字段名 `_portNote`，下划线前缀表示元数据（非平台消费字段）
- 内容必须包含：**当前端口值** + **登记表路径** + **同步提醒**
- `manifest.json` 与 `tool.json` 两份都要加，且端口值必须一致

## 二、README 加「平台版」说明段

在每个平台版工具仓库的 README 里，**紧跟标题下方**插入一段（不要在文末，容易被忽略）：

```markdown
## 平台版（tools-center）

| 项 | 值 |
|---|---|
| 工具 id | `clipboard` |
| 平台端口 | **8130** |
| 健康检查 | `/health` |
| 访问地址 | `http://<平台地址>/tool/clipboard/` |

> ⚠️ **端口由 [tools-center](https://github.com/Simiely/tools-center) 统一分配**，
> 登记表见 [`docs/ports.md`](https://github.com/Simiely/tools-center/blob/main/docs/ports.md)。
> **改端口前必须先查登记表**，改完同步更新登记表与仓库内所有声明文件。
```

三个仓库的具体取值：

| 仓库 | 工具 id | 端口 | 健康检查 |
|---|---|---|---|
| clipboard-tool | `clipboard` | 8130 | `/health` |
| gh-release-center | `gh-release-center` | 8132（本次迁入） | `/health` |
| workbuddy-credits-tool | `wb-credits` | 8123 | `/api/status` |

## 三、AGENTS.md 技术栈行加登记表引用

在「技术栈」段平台那一行补一句，AI 改代码时会先读到：

```diff
- - 平台：tools-center（manifest V2，`runtime: node` + `entry: server.mjs` + `port: 8130` + `capabilities: ["storage"]`）
+ - 平台：tools-center（manifest V2，`runtime: node` + `entry: server.mjs` + `port: 8130` + `capabilities: ["storage"]`）
+ - **端口 8130 由 tools-center 统一分配，登记表 `tools-center/docs/ports.md`；改端口 = 改登记表 + 改仓库声明文件，两处同步**
```

## 四、发布规范 checklist 新增项

在各工具的 `docs/发布规范.md`「前置验证」或「打包」checklist 里加两条：

```diff
  ### 1. 前置验证
  - [ ] 全量测试通过
+ - [ ] **端口已登记在册**：`tools-center/docs/ports.md` 第二节有本工具的一行，端口值与声明文件一致
+ - [ ] **双声明文件端口一致**：`manifest.json` 与 `tool.json` 的 `port` 相同；
+       `tool.json` 的 `cmd` 数组末位端口参数与 `port` 字段相同（V1 硬编码，漏改则进程监听旧端口、平台探新端口 → 永远 down）
  - [ ] 副本实测可启动（health OK、版本指纹正确）
```

clipboard-tool 的 `docs/发布规范.md` 第三节「平台版 zip 结构」里已有 tool.json 字段规范，
在那段的字段列表后追加同样的两条即可。

## 六、为什么"标记"能防住问题

仅靠文档无法防止下次再撞，所以三层标记各有分工：

| 层 | 防的是什么 |
|---|---|
| `_portNote` 字段 | AI/人改声明文件时**当场看到**提醒（改端口必然要打开这个文件） |
| README 平台版段 | 新接入工具时**先看到**登记表链接（README 是仓库入口） |
| 发布规范 checklist | 发版**最后一道关口**（端口没登记就不许打包） |
