# 架构梳理:主干框架 vs 附加模块

> 目的:理清 tools-center 哪些是**主干框架**(去掉就无法托管工具),哪些是**附加模块**(围绕主干的接入/管理/扩展)。
> 原则:**足够简单、清晰**——每个文件单一职责,主干闭环一目了然。

## 总览

- 代码规模:约 4800 行 / 48 个文件(不含 node_modules),零第三方运行时依赖
- 入口:`server.mjs`(薄层:HTTP 装配 + 路由分发 + WS 转发)
- 路由:按域拆分到 `lib/routes/`,由 `lib/routes/index.js` 合并与匹配

## 🟢 主干框架(9 个文件,约 900 行)

让"工具托管"跑起来的最小闭环:

```
server.mjs ──▶ lib/routes/index.js(路由注册表+匹配器)
                    │
                    ▼
┌─ lib/core/config.js    全局配置:路径 / 工具端口段 8100-8199 / 参数
├─ lib/core/manifest.js  tool.json 校验规则
├─ lib/core/registry.js  注册表:扫描 tools/*/tool.json → Map<id, ToolSpec>(核心)
├─ lib/core/lifecycle.js 工具状态标记:paused / removed
├─ lib/core/manager.js   进程管理:启动 / 停止 / 健康检查 / 崩溃退避拉起
├─ lib/core/proxy.js     反向代理:/tool/<id>/ → 工具端口(注入 __BASE__)
└─ lib/core/logger.js    工具日志采集 / 内存查看 / 落盘(7 天)
```

**主干闭环**:创建工具 → registry 注册 → manager 启动进程(8100-8199)→ proxy 反代访问 → 30s 健康检查、崩溃退避拉起 → logger 看日志。

判据:**去掉某个文件后,工具是否还能被创建、运行、访问?不能 = 主干。**

## 🔵 附加模块(按用途分组)

| 分组 | 模块 | 职责 |
|---|---|---|
| **工具接入** | `lib/core/upload.js` `lib/routes/tools-files.js` `lib/core/git.js` `lib/core/zip.js` | zip 上传/解压自动创建、git 仓库导入、zip 链接导入(下载+进度) |
| **存储管理** | `lib/core/disk-ops.js` `lib/routes/disk.js` | 磁盘残留扫描/分类/清理(托管/无效/解除/幽灵)+ 程序/数据/垃圾三分类 |
| **备份** | `lib/core/backup.js` `lib/core/toolbackup.js` `lib/routes/backup.js` | 平台数据备份(WebDAV)/ 工具全量备份 zip 可还原 |
| **云同步** | `lib/core/webdav.js` `lib/routes/webdav.js` | WebDAV 配置 + 备份上传/下载 |
| **安全** | `lib/core/auth.js` `lib/routes/admin.js` | 管理密码(可选) |
| **能力扩展** | `lib/capabilities/`(browser/storage/network)`lib/sdk.js` `lib/core/capability.js` | 平台提供给工具的"环境模块",懒加载(当前实验性) |
| **功能开关** | `lib/core/settings.js` `lib/routes/admin.js`(settingsRoutes) | 附加模块启停(v0.11.7+):`data/settings.json` + env 覆盖,路由按开关过滤 |
| **模块注册表** | `lib/core/modules.js` | 附加模块清单单一事实来源(v0.11.8+):key/名称/说明/默认开关,settings 与 routes 共用 |
| **数据识别** | `lib/core/data-classify.js` | 程序/数据/垃圾三分类公共层(v0.11.8+):disk-ops 与 tools-files 共用,附加模块不互依赖 |

前端对应:
- **主干**:`public/index.html` + `js/api.js` `app.js` `ui.js` `cards.js` `detail.js`(工具列表/添加/卡片/详情)
- **附加**:`js/disk-page.js` + `disk.html`(存储管理独立页)

> **附加模块全部可开关(v0.11.7+)**:顶栏「设置」管理;关闭后路由不注册(后端 404)+ 前端入口隐藏。`lib/routes/index.js` 中每组路由带 `module` 标识(必须来自 `lib/core/modules.js` 注册表),主干组无标识恒注册。
> **公共层约定(v0.11.8+)**:被多个附加模块共用的能力(如数据识别)必须抽到 `lib/core/` 独立文件,附加模块之间禁止直接 import(避免耦合)。

## 🔌 如何新增一个附加模块(4 步)

> 微内核"扩展点"规范:加一个新模块不动主干,按此流程走。

1. **注册**(`lib/core/modules.js`):`MODULES` 数组加一项 `{ key, name, desc, defaultOn: true }`——开关/设置页/路由过滤自动生效
2. **实现**(`lib/core/xxx.js` + `lib/routes/xxx.js`):核心逻辑放 core,HTTP 接口放 routes 并导出路由数组
3. **挂载**(`lib/routes/index.js`):`GROUPS` 加一组 `{ routes: xxxRoutes, module: "<key>" }`(主干功能不加 module)
4. **前端入口**(`public/index.html` + `app.js` 的 `loadSettings()`):加按钮 + 按开关隐藏

完成为止共改 4 处,主干零改动。删除模块 = 反向 4 步 + 删文件。公共能力(如数据识别)抽到 `lib/core/` 独立模块供复用。

## 📊 一条工具的生命周期

```
接入  拖 zip / git 链接 / zip 链接 → 解压到 tools/<id>/ → scanTools 注册
运行  registry 校验 → manager.start(端口 8100-8199) → proxy 反代 /tool/<id>/
守护  healthCheck 30s 轮询 → 崩溃退避拉起(1s,2s,4s…封顶 30s,连续 5 次失败标记 error)
数据  存在工具自己的目录 tools/<id>/(程序+数据混存 ← 存储管理两列化改造中)
管理  disk-ops 扫描分类 / backup·toolbackup 备份 / webdav 同步 / auth 密码
```

## ✂️ 已识别的简化点(供后续优化)

1. **`lib/routes/tools-files.js`(270 行)偏胖**:zip 上传 + 链接导入 + 下载代理(CONNECT 隧道)+ 导入进度任务全挤一处 → 建议把"导入任务"拆到独立模块(`lib/core/import-task.js`),路由只留转发
2. **前端 `js/disk.js`(149 行)**:存储管理改造为独立页面后删除(代码净减)
3. **capabilities(browser/storage/network)**:当前实验性,不用则冻结标注(保留,勿删)
4. **根目录文档偏多**(PLAN/PLAN-V2/DESIGN/DEVELOPMENT):可合并精简,`docs/` 为文档主目录
5. **存储管理数据识别**:程序和数据库文件混存 → 计划引入 `dataFiles` 声明 + 平台通用规则,见存储管理改造计划
