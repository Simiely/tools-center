# 端口分配登记表

> **本文件是 tools-center 平台所有工具端口的唯一真源（Single Source of Truth）。**
> 任何工具仓库在写 `manifest.json` / `tool.json` 的 `port` 字段前，**必须先查这张表**。
> 改端口 = 改这张表 + 改对应仓库的声明文件，两处同步，缺一不可。

最后更新：2026-08-29

---

## 一、端口段划分

| 端口段 | 用途 | 谁在用 | 能否手动占用 |
|---|---|---|---|
| `8080` | 平台主程序（`PORT` 环境变量可改） | tools-center 自身 | — |
| `8100 – 8189` | **工具端口段** | 所有 app 型工具 | ✅ 需登记 |
| `8190 – 8199` | **临时/测试保留区** | 冒烟测试、mock 服务、临时调试 | ❌ 禁止作为工具端口 |
| `8200 – 8299` | 能力模块端口段（`CAP_PORT_MIN/MAX`） | browser / storage / network | ❌ 平台自用 |

> **为什么单留 8190–8199**：测试进程（如 clipboard 的 mock-webdav）与工具进程可能同机并存，
> 测试端口若落在工具段内，跑测试时会撞掉正在运行的工具。划出独立保留区后互不影响。

## 三、分配规则

1. **在册者优先**：端口以本表登记顺序为准，后到者让位。冲突时改后到者，不动已稳定运行的一方。
2. **一个端口一个工具**：平台 `registry.scanTools` 检测到重复时，后扫到的工具被标记 invalid。
3. **⚠️ 冲突表现是随机的**：`scanTools` 用 `fs.readdirSync` 遍历目录，Linux/overlayfs（Docker 环境）**不保证字母序**，
   所以两个撞车工具谁被标 invalid 取决于文件系统返回顺序——可能重启容器后"挂掉的那个"换人了。
   排查时不要凭"上次是 A 挂"下结论，直接看卡片报错或 `GET /api/tools`。
4. **端口随 id 走，不随仓库走**：工具改名/改 id 不释放端口；工具下线后端口进入**冷却期 30 天**再释放
   （避免残留实例或旧备份重新上线时撞车）。
5. **不要用"看起来没人的"端口**：`8190–8199`、`8200–8299` 是保留段，即使当前空着也不分配。
6. **测试端口单独约定**：新工具的测试脚本一律用 `8190–8199`，禁止占用工具段。
   clipboard 的 `8131` / `8180` 是历史遗留，已在本表登记保护，不再分配给任何工具。

## 四、新工具接入流程

1. 查本表第二节，挑一个 `8133 – 8189` 范围内的空闲端口
2. 在**本表第二节新增一行**（端口 + 工具 id + 名称 + 仓库链接）
3. 在工具仓库写 `manifest.json` / `tool.json`，`port` 填同一个值
4. 工具仓库 README 加「平台版」说明段（见 [仓库内端口标记规范](./仓库内端口标记规范.md)）
5. 部署后验证：平台首页卡片无「端口冲突」红标，健康检查通过

> 改端口时必须同步的位置，见 [端口改动清单](./仓库内端口标记规范.md)。

---

## 五、冲突发生时的处理

平台当前行为：`registry.scanTools` 发现两工具同端口 → 后扫到的标记 invalid，卡片显示
`端口 XXXX 与 <id> 冲突`，该工具不启动。

处理步骤：
1. 查本表确认谁是在册方（在册者不动）
2. 让位方按 [端口改动清单](./仓库内端口标记规范.md) 改掉所有位置
3. 重新打包发布，平台刷新重扫
4. 回本表更新端口记录

## 七、平台侧对应代码位置

| 关注点 | 文件 | 说明 |
|---|---|---|
| 端口段常量 | `lib/core/config.js` | `TOOL_PORT_MIN` / `TOOL_PORT_MAX` / `CAP_PORT_MIN` / `CAP_PORT_MAX` |
| 端口冲突检测 | `lib/core/registry.js` → `scanTools()` | 同段内重复 → 标记 invalid |
| 端口范围校验 | `lib/core/registry.js` → `validate()` | 不在段内 → 报错 |
| 自动分配空闲端口 | `lib/core/registry.js` → `createTool()` | 取段内最小空闲 |
| 健康探测 | `lib/core/manager.js` → `healthCheck()` | `GET http://127.0.0.1:<port><health>` |
