# 使用指南 · 怎么接入你的小工具

> 工具中心只要求你的工具做一件事:**能监听一个 HTTP 端口**。剩下的(入口、托管、健康检查、日志、崩溃重启)全交给它。
> **接入 = 把文件放进 `tools/<id>/` 目录(带一个 `tool.json`)→ 刷新首页 → 工具自动出现并启动。** 就这么简单。

---

## 一、目录结构规范(核心)

所有工具都放在平台的 `tools/` 目录下,**一个工具一个子目录**:

```
tools-center/
├── server.mjs            # 平台主程序
├── lib/                  # 平台模块(不用动)
└── tools/                # ★ 工具目录:放一个文件夹 = 添加一个工具
    ├── wb-credits/       # 示例:你的积分工具
    │   ├── tool.json     # 工具声明(必须有)
    │   ├── wb-gui.mjs    # 你的代码(任意文件,任意语言)
    │   ├── lib/          # 子目录随便建(平台按原样保留)
    │   └── wb-accounts.json   # 工具自己的数据
    └── my-tool2/         # 未来的下一个工具…
```

**平台会做两件事:**
1. **自动发现**:每次首页/`/api/tools` 被访问时,自动扫描 `tools/*/tool.json`
   → **你放好文件、刷新一下页面,新工具就出现了**(不用重启、不用调 reload)
2. **自动启动**:新发现的 app 型工具立即拉起子进程;删掉目录后刷新,工具自动停止消失

---

## 二、两种工具类型

| 类型 | 适用 | 工具中心做什么 |
|---|---|---|
| `app` | **你自己写的工具**(Node/Python/任何能起 HTTP 服务的东西) | spawn 托管进程、崩溃自动拉起、健康检查、日志聚合、`/tool/<id>` 反向代理 |
| `link` | **外部已有服务**(NAS 上独立容器/套件,如 Jellyfin、网盘) | 只在首页生成一张卡片,点击跳转到 url;不托管、不占端口 |

---

## 三、接入方式一:放目录(推荐,最直接)

### 步骤(以 app 型为例)

```bash
# 1. 建目录:tools/<id>/   (id = 小写字母/数字/连字符)
mkdir -p tools/tomato

# 2. 把你的工具文件拷进去(任意结构,可带子目录)
cp -r ~/my-tool/* tools/tomato/

# 3. 写 tool.json(见下方"tool.json 规范")
cat > tools/tomato/tool.json <<'EOF'
{
  "id": "tomato",
  "name": "番茄钟",
  "desc": "25 分钟专注计时",
  "group": "效率",
  "icon": "🍅",
  "type": "app",
  "cmd": ["node", "server.mjs", "8130"],
  "port": 8130,
  "health": "/api/health"
}
EOF

# 4. 完成!刷新首页(http://IP:8080)→ 卡片出现并自动启动
```

link 型同理,目录里只需要 `tool.json` 一个文件:

```json
{ "id": "jellyfin", "name": "影音库", "desc": "独立容器", "group": "服务",
  "icon": "🎬", "type": "link", "url": "http://192.168.1.100:8096" }
```

### 工具代码怎么写(最小示例,Node)

```js
// server.mjs —— 任何能监听端口的程序都行
import http from "node:http";
const port = parseInt(process.argv[2] || "8130", 10);
http.createServer((req, res) => {
  res.writeHead(200, { "Content-Type": "application/json; charset=utf-8" });
  res.end(JSON.stringify({ ok: true, path: req.url }));
}).listen(port, "127.0.0.1");
```

要点:
- **端口从命令行参数读**(`cmd` 里最后一个参数就是端口)
- 监听 `127.0.0.1` 即可(平台内部转发,无需对外监听)
- 数据文件写在**自己目录下** `tools/<id>/`(挂载卷,换容器不丢)

### 子路径挂载约定(重要,页面资源必须遵守)

工具在平台上以 `/tool/<id>/` 子路径访问,**页面里的资源引用不能写死绝对路径**,否则独立运行正常、挂载后 JS/图片 404(按钮全部失效)。

| 引用类型 | 错误写法 | 正确写法 |
|---|---|---|
| 页面资源(script/css) | `<script src="/app.js">` | `<script src="./app.js">`(相对路径,平台自动解析到 `/tool/<id>/app.js`) |
| 内部 API | `fetch("/api/xxx")` | `fetch(__BASE__ + "/api/xxx")` |
| 跳转下载 | `location.href = "/api/export"` | `location.href = __BASE__ + "/api/export"` |

`__BASE__` 由**平台自动注入**(HTML 响应会插入 `window.__BASE__="/tool/<id>"`;独立运行时不注入,此时自行检测为空):
```html
<script>window.__BASE__ = window.__BASE__ || (location.pathname.match(/^\/tool\/[^/]+/) || [""])[0];</script>
```
放在你的 JS 之前即可。**纯后端工具(返回 JSON,不含页面)无需关心此项。**

## 四、接入方式二:网页在线添加(不用碰服务器文件)

1. 首页右上角 **「+ 添加」** → 填**名称** → 保存
   - 自动生成 id / 分配空闲端口 / 生成可运行示例 / 自动启动
2. 传代码:弹窗里 **点击或拖拽 zip 包**(自动解压)→ 创建 + 上传 + 启动一气呵成
3. 想精确控制:展开 **「高级设置 ▸」** 改 id / 描述 / 分组 / 图标 / 启动命令 / 端口 / 健康检查

> **零输入上传(zip 直接导入,v0.11.3+)**:**什么都不用填**——直接把带 `tool.json` 的 zip 拖进弹窗即可。
> 平台自动从 zip 内 `tool.json` 读取名称/端口/命令并创建、启动;同一 id 再次上传 = 覆盖更新(升级工具)。zip 内声明文件可在顶层或单层子目录(`tool.json` / `manifest.json`)。示例:积分仪表盘部署包(见第十章)。

> **Git / 链接导入零输入(v0.11.4+)**:**名称可留空**——「Git 导入」模式填**仓库地址或 Release 的 .zip 链接**后直接点保存:
> - `.zip` 链接 → 平台下载 zip,从 `tool.json` 自动创建(与拖 zip 同链路);同一 id 再导 = 覆盖升级
> - Git 仓库 → 自动识别 `tool.json`/`manifest.json`(根或一级子目录),id 从 URL/声明推导,名称取声明 `name`(缺省用 id)
> - 链接下载支持 `HTTPS_PROXY`/`HTTP_PROXY` 环境变量(代理环境访问 GitHub Release 资产)
> - **导入进度(v0.11.5+)**:点保存后按钮变「⏳ 导入中…」,顶部进度条实时显示阶段与百分比(下载中→解压/克隆→创建→启动→完成;失败变红显示原因),不再干等——下载/导入耗时较长时尤其有用

> **界面说明**:首页顶部为置顶导航栏(统计 + 刷新 + 添加),下方为分类标签(按 tool.json 的 `group` 自动生成,可横向滑动),卡片按分组展示。手机端固定 3 列大图标卡片。

## 五、tool.json 规范(字段速查)

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `id` | string | ✅ | 唯一标识,`[a-z0-9-]`,与目录名一致 |
| `name` | string | ✅ | 显示名称(中文) |
| `type` | string | — | `app`(默认)/ `link` |
| `url` | string | link 必填 | link 型目标地址(http/https) |
| `cmd` | string[] | app 必填 | 启动命令,如 `["node","server.mjs","8130"]` |
| `port` | number | app 必填 | 监听端口(8100~8199,段内可用) |
| `desc` | string | — | 卡片一句话描述 |
| `group` | string | — | 首页分组,默认"其他" |
| `icon` | string | — | 卡片图标(emoji),默认 🧰 |
| `health` | string | — | 健康检查路径,GET 返回 2xx 视为健康 |
| `cwd` | string | — | 工作目录(相对工具目录,默认 `.`) |
| `env` | object | — | 注入的环境变量 |
| `restart` | string | — | `always`(默认)/ `on-failure` / `no` |
| `hidden` | boolean | — | 不在首页显示(仍可直达) |

校验规则(不满足则该工具标记"无效",卡片显示原因):
- `id` 必须 `[a-z0-9-]`;`name` 必填
- app 型:`cmd` 非空数组;`port` 在 8100~8199;同一端口只允许一个工具
- link 型:`url` 必须 http(s)://

## 六、API 参考(接口一览)

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/` | 首页(每次加载自动扫描工具目录) |
| GET | `/api/tools` | 工具列表(含状态);**访问即重扫+增量启动** |
| POST | `/api/tools` | 在线创建工具(body = tool.json 内容,缺省字段自动补全) |
| DELETE | `/api/tools` | 删除工具(body `{"id":"xxx"}`,先停进程再删目录) |
| POST | `/api/tools/<id>/restart` | 重启指定 app 工具 |
| POST | `/api/tools/<id>/upload` | 上传单个文本文件到工具目录(body `{"name":"相对路径","content":"..."}`,支持子目录) |
| POST | `/api/files` | 通用文件上传:multipart(`path`+`file`) 或 JSON(`path`+`content`+`encoding:base64`);**.zip 自动解压到目标目录** |
| POST | `/api/reload` | 手动重扫 + 增量同步(平时刷新页面即可) |
| GET | `/api/logs/<id>?lines=N` | 工具日志(最近 N 行,默认 200) |
| GET | `/tool/<id>[/...]` | 访问工具:app 反向代理 / link 302 跳转 |

> 所有 API 返回 JSON `{ ok, ... }`,错误时 `{ ok: false, error: "原因" }`。

## 七、删除 / 更新工具

- **删除**:卡片右下角 🗑(或 `DELETE /api/tools`,body `{"id":"xxx"}`)→ 删除整个 `tools/<id>` 目录(**删除前自动备份**,见下)
- **更新**:
  - 改 `tool.json` 或换代码 → **刷新首页即生效**(自动重扫)
  - 改了 `cmd`/`port` → 刷新后自动按新配置重启
  - 只换代码文件 → 刷新页面即可(目录存在,配置没变,进程不重启,代码改动需手动重启该工具 `POST /api/tools/<id>/restart`)
  - **zip 覆盖升级(v0.11.6+)**:重新上传同一工具的 zip → 程序替换,**数据文件自动保留**(按 `dataFiles` 声明 + 通用规则),不再清空数据

## 七·二、存储管理:程序 / 数据 分列(v0.11.6+,独立页)

> 顶栏「**存储**」→ 新窗口打开 `/disk.html`。每个工具一行,左列**程序**、右列**数据**,分开标注,不再混在一起。

### 两列各看什么

| 列 | 内容 | 说明 |
|---|---|---|
| **程序** | 名称/类型/端口/托管状态/程序体积 | 代码可重建(zip/git 来源);删除工具 = 程序+数据一并删 |
| **数据** | 数据文件明细(名+大小)+ 合计 | 用户数据(`*.db*`、`wb-*.json`、`data/` 等),可**单独清理** |
| **垃圾** | `upload.zip`、`.tmp-*` 等临时残留 | 独立标注,不占数据不占程序 |

### 关键能力

- **⚠️ 数据残留可回收**:程序已删除/失效但数据仍在 → 顶部统计 + 行内红色标注,可单独「清理数据」回收磁盘
- **清理数据**:只删数据文件、保留程序代码(二次确认时列出将删的每个文件)
- **删除/清理前自动备份**:每次删除工具、清理目录、清理数据,都会先自动打包到 `data/backups/tools-<时间戳>.zip`(提示"已备份可还原"),误删可恢复
- **挂载点工具**:标注"独立挂载,需在宿主层处理"(平台无法物理删除)
- **数据识别规则**:平台通用(数据库三件套 `*.db*`、`data/ logs/ uploads/` 目录、`.env` 等)+ 工具 `tool.json` 的 `dataFiles` 声明(glob)叠加;`tool.json/manifest.json/package.json` 等程序核心文件**永不**归数据、不可删

## 七·三、功能开关(附加模块可启停,v0.11.7+)

> 顶栏「**设置**」→ 弹窗列出所有附加模块开关。**主干框架(工具托管/访问/日志/设置本身)不可关**,关闭的模块:前端入口隐藏 + 后端接口 404。

| 模块 | 默认 | 关闭后 |
|---|---|---|
| 存储管理 | 开 | 首页「存储」按钮消失,`/api/admin/disk` 404 |
| 备份 | 开 | 「备份」按钮消失,备份/恢复接口 404 |
| WebDAV 云同步 | 开 | WebDAV 相关接口 404 |
| 管理密码 | 开 | 「密码」按钮消失,`/api/admin/pass` 404(设置开关免密,仍可开回) |
| 能力模块 | 开 | 能力状态/ensure 接口 404 |
| 在线导入 | 开 | 「+ 添加」隐藏 Git 导入与 zip 拖拽(仅保留名称创建),导入接口 404 |

- **存储**:`data/settings.json`(运行时目录,持久化);**环境变量可覆盖**(`MODULES_STORAGE=0` / `MODULES_WEBDAV=false` 等,容器部署友好)
- **生效方式**:保存后**重启生效**(路由在启动时构建)
- **开关清单**(模块 key):`storage` / `backup` / `webdav` / `auth` / `capabilities` / `import`

## 七·五、备份 / 恢复工具(v0.10+)

> **防误删**:删除工具前先备份,删错了可以从备份恢复(代码+数据全包)。

### 网页操作(推荐)
顶栏「**备份**」按钮 → 弹窗:
- **立即备份**:把当前所有工具(`tools/<id>/` 全部文件)打包成 zip,存到 `data/backups/tools-<时间戳>.zip`
- **备份列表**:显示每份备份的时间/大小/包含哪些工具,可**下载**到本地存档
- **恢复所选**:勾选某份备份里的工具 → 「恢复所选」→ 工具目录整体还原
  - 目标已存在时,自动先把现有目录改名为 `<id>.pre-restore-<ts>`(不会覆盖误伤)
  - 恢复后平台自动重新扫描并重启该工具

### API
| 接口 | 方法 | 说明 |
|---|---|---|
| `/api/tools/backup` | POST | 执行备份,返回 `{file, size, tools[]}` |
| `/api/tools/backup` | GET | 备份列表(含每份的工具清单) |
| `/api/tools/backup/restore` | POST | 恢复,body `{backup:"tools-xxx.zip", tools:["id1","id2"]}` |
| `/api/tools/backup/download` | GET | 下载,`?file=tools-xxx.zip` |

### 注意
- 备份 zip 存在 `data/backups/`(挂载卷,换镜像/删容器不丢)
- 备份包含**代码 + tool.json + 运行数据**(如 `wb-accounts.json`),恢复后数据一起回来
- 备份文件本身未加密,含工具数据,注意本地存档安全

## 八、部署到 NAS(Docker)

```bash
# 1. 把本项目拷到 NAS(如 /volume1/docker/tools-center),先建目录
mkdir -p tools data

# 2. 构建并启动(群晖:Container Manager → 项目 → 选 docker-compose.yml)
docker compose up -d --build

# 3. 访问 http://NAS-IP:8080
```

- 容器内以 **uid 1000(node)** 运行:挂载目录权限用
  `sudo chown -R 1000:1000 tools data`(或 File Station 设置)
- 端口冲突:DSM 占用 80/443/5000/5001,工具中心默认 8080,可用 `PORT` 环境变量改
- **添加工具 = 往挂载卷的 `tools/` 目录放文件夹**(SSH 拷入或网页上传),刷新即出
- 远程访问:建议 **Tailscale** 组网,不暴露公网端口

## 九、常见问题

| 现象 | 处理 |
|---|---|
| 放好目录刷新没出现 | 确认目录名是 `[a-z0-9-]`、有 `tool.json`;看卡片是否显示"配置错误"原因 |
| 卡片显示"端口冲突" | 两个 app 用了同一端口 → 改其中之一的 `port` |
| 卡片红点/异常 | 查看日志:`GET /api/logs/<id>` 或 `data/logs/<id>.log` |
| 工具反复重启 | 启动即崩溃 → 看日志;退避 5 次后标记 error 停止 |
| 端口 8080 被占 | `PORT=9090 docker compose up`(平台端口,与工具端口段无关) |
| 工具进程在跑但卡片显示 stopped | 老版本 bug,已修复(v0.4.0+);升级后正常 |
| 「添加当前账号」提示"浏览器代理未运行" | 平台只托管了工具本体,其依赖的辅助进程(edge-daemon)需**一并接入**:把它也做成 app 工具(`cmd:["node","edge-daemon.mjs","8129"]`,`port:8129`,`health:/status`,restart always),平台自动托管+崩溃自愈;并确认 Edge 以 `--remote-debugging-port=9222` 启动 |
| 存储管理里出现"幽灵目录"删不掉 | 该目录是 **Docker 独立挂载点**(bind mount)时,平台无法物理删除(容器内不能卸载宿主挂载,报 EBUSY)。需在**宿主机**处理:删挂载源目录或改 compose 去掉该挂载行,再 `docker compose down && up -d` 重建。详见部署文档「独立仓库挂载警告」 |
| 清理提示"已清理"但刷新又出现 | v0.11.2 已修复(删除失败会保留标记+说明原因)。若仍出现:确认挂载点残留(同上),或浏览器强刷(Ctrl+F5) |
| 底部版本号显示的是什么 | v0.11.1+ 页面底部固定显示 `Tools Center vX.Y.Z`(读镜像内 package.json),用于确认 Docker 升级是否生效 |

## 十、已接入示例:积分仪表盘(wb-credits)

> **本平台首个完整接入示例**,同时是双向标注的一侧(工具侧对应文档:`workbuddy-credits-tool/docs/tools-center部署.md`)。

| 项 | 值 |
|---|---|
| 工具仓库 | [github.com/Simiely/workbuddy-credits-tool](https://github.com/Simiely/workbuddy-credits-tool)(独立仓库) |
| 工具 id / 目录 | `wb-credits`(`tools/wb-credits/`) |
| 接入方式 | app 托管:`tool.json` 声明,`cmd:["node","wb-gui.mjs","8123"]`,`port:8123`,`health:/api/status` |
| 访问地址 | `/tool/wb-credits/`(子路径,工具前端已用 `__BASE__` 适配) |

### 与平台的联系(三个形态数据互通)

```
tools-center(平台版,file 采集,WebDAV 同步)
      ↕  WebDAV「云同步上传/下载」(账号池 + 积分历史)
Windows 桌面:exe 版(单文件,Edge 采集 cookie)→ 源码版(edge-daemon)
```

- **cookie 凭证只在桌面端采集**(平台容器无浏览器):桌面端重新登录 →「添加当前账号」→「☁️ 上传」→ 平台版「☁️ 下载」即更新
- **数据目录 = 工具目录**(`tools/wb-credits/`):`credits.db` 含凭证,删工具 = 删数据,先云同步备份
- 工具侧文档:`docs/tools-center部署.md`(接入规范)/ `docs/发布规范.md`(发包 = 平台版 zip + exe 版)
