# 使用指南 · 怎么接入你的小工具

> 工具中心只要求你的工具做一件事:**能监听一个 HTTP 端口**。剩下的(入口、托管、健康检查、日志、崩溃重启)全交给它。
> 添加工具 = **放目录 + 写 `tool.json`**;或在网页上点「＋ 添加工具」直接填。

## 一、两种工具类型

| 类型 | 适用 | 工具中心做什么 |
|---|---|---|
| `app` | **你自己写的工具**(Node/Python/任何能起 HTTP 服务的东西) | spawn 托管进程、崩溃自动拉起、健康检查、日志聚合、`/tool/<id>` 反向代理 |
| `link` | **外部已有服务**(NAS 上独立容器/套件,如 Jellyfin、网盘) | 只在首页生成一张卡片,点击跳转到 url;不托管、不占端口 |

## 二、添加 app 型工具(自己写的工具)

### 方式 A:网页在线添加(推荐,极简)

1. 打开工具中心首页 → 点右上角 **「＋ 添加工具」**
2. **只需填名称**,点「保存并启用」——工具中心自动完成:
   - 自动生成 id、自动分配空闲端口(8100~8199)
   - 自动生成一份**可运行的示例代码**(`tools/<id>/server.mjs`)
   - 自动启动,首页立刻出现卡片,打开就能访问
3. 换成你的工具:**用你的代码覆盖 `tools/<id>/server.mjs`**,点卡片重启即可

> 想自定义?点「▸ 高级设置」展开,可改 id/描述/分组/图标/启动命令/端口/健康检查。
> 规则:你的工具只需**监听自动分配的端口**(从命令行参数读,示例已示范)。

### 方式 B:手动放文件(进阶)

```bash
mkdir -p tools/tomato
# 把你的工具文件放进去(如 server.mjs)
cat > tools/tomato/tool.json <<'EOF'
{
  "id": "tomato",
  "name": "番茄钟",
  "desc": "25 分钟专注计时",
  "group": "效率",
  "icon": "🍅",
  "type": "app",
  "cmd": ["node", "server.mjs", "8130"],
  "port": 8130,
  "health": "/api/health"
}
EOF
curl -X POST http://127.0.0.1:8080/api/reload   # 热加载
```

### 工具代码怎么写(最小示例,Node)

```js
// server.mjs —— 任何能监听端口的程序都行
import http from "node:http";
const port = parseInt(process.argv[2] || "8130", 10);
http.createServer((req, res) => {
  res.writeHead(200, { "Content-Type": "application/json; charset=utf-8" });
  res.end(JSON.stringify({ ok: true, path: req.url }));
}).listen(port, "127.0.0.1");
```

要点:
- 端口从命令行参数读(`cmd` 里最后一个是端口),或读环境变量
- 监听 `127.0.0.1` 即可(工具中心内部转发,无需对外监听)
- 数据文件写在**自己目录下** `tools/<id>/`(挂载卷,换容器不丢)

## 三、添加 link 型工具(外部服务)

```json
{ "id": "jellyfin", "name": "影音库", "desc": "独立容器", "group": "服务",
  "icon": "🎬", "type": "link", "url": "http://192.168.1.100:8096" }
```

- 目录里**只需要这一个文件** `tools/jellyfin/tool.json`,无任何代码
- 网页在线添加同样支持:选 `link` 类型,填 url 即可

## 四、删除 / 更新工具

- **删除**:卡片右下角 🗑 → 确认(删除整个 `tools/<id>` 目录)
- **更新**:
  - 改 `tool.json` → `curl -X POST /api/reload`(或重启容器)
  - 换代码文件 → 直接覆盖文件后重启该工具(`POST /api/tools/<id>/restart`)
  - 在线重建:先删再按新配置添加

## 五、部署到 NAS(Docker)

```bash
# 1. 把本项目拷到 NAS(如 /volume1/docker/tools-center),先建目录
mkdir -p tools data

# 2. 构建并启动(群晖:Container Manager → 项目 → 选 docker-compose.yml)
docker compose up -d --build

# 3. 访问 http://NAS-IP:8080
```

- 容器内以 **uid 1000(node)** 运行:挂载目录权限用
  `sudo chown -R 1000:1000 tools data`(或 File Station 设置)
- 端口冲突:DSM 占用 80/443/5000/5001,工具中心默认 8080,可用 `PORT` 环境变量改
- 远程访问:建议 **Tailscale** 组网,不暴露公网端口

## 六、tool.json 字段速查

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `id` | string | ✅ | 唯一标识,`[a-z0-9-]` |
| `name` | string | ✅ | 显示名称 |
| `type` | string | — | `app`(默认)/ `link` |
| `url` | string | link✅ | link 型目标地址 |
| `cmd` | string[] | app✅ | 启动命令,如 `["node","server.mjs","8130"]` |
| `port` | number | app✅ | 监听端口(8100~8199) |
| `desc` / `group` / `icon` | string | — | 卡片描述/分组/图标 |
| `health` | string | — | 健康检查路径(返回 2xx 视为健康) |
| `cwd` | string | — | 工作目录(相对工具目录,默认 `.`) |
| `env` | object | — | 注入的环境变量 |
| `restart` | string | — | `always`(默认)/ `on-failure` / `no` |
| `hidden` | boolean | — | 不在首页显示 |

## 七、常见问题

| 现象 | 处理 |
|---|---|
| 卡片显示"端口冲突" | 两个 app 用了同一端口 → 改其中之一的 `port` |
| 卡片红点/异常 | 点开卡片看?查看日志:`GET /api/logs/<id>`,或工具中心日志 `data/logs/<id>.log` |
| 工具反复重启 | 启动即崩溃 → 看日志;退避 5 次后标记 error 停止 |
| 添加后首页没出现 | 确认 `tool.json` 校验通过(卡片会显示配置错误原因);或重启容器 |
| 端口 8080 被占 | `PORT=9090 docker compose up`(工具中心) |
| 网页添加 app 报"端口需 8100~8199" | 端口段是约定,超范围拒绝 |
