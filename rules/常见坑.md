# 常见坑 · 详细清单

> AGENTS.md 的 @引用细节。开发中踩到新坑,一坑一条追加(与 knowledge-base 同格式:TL;DR / 问题 / 根因 / 解决 / 预防)。

## 1. gitignore 行尾注释不生效

**TL;DR**:gitignore 中 `#` 只在**行首**是注释;`wb-accounts.json # 凭证` 整行会成为文件名 pattern,导致敏感文件被误提交。

- 问题:写了带行尾注释的规则,凭证文件仍被 `git add` 暂存
- 根因:gitignore 语法不支持行尾注释,`#` 后面的内容并入 pattern
- 解决:注释独立成行;误暂存用 `git rm --cached <file>` 移除
- 预防:提交前 `git status` 检查;凭证类文件规则单独一行

## 2. 子进程"崩溃风暴"(无限快速重启)

**TL;DR**:工具启动即崩溃时,无退避会以毫秒级疯狂重启,日志刷爆、CPU 打满。

- 问题:启动失败的工具体现为反复 spawn/exit
- 根因:manager 无条件立刻重启
- 解决:指数退避 1s/2s/4s…封顶 30s;连续失败 N 次标记 `error` 停止拉起
- 预防:任何拉起逻辑必须带退避 + 上限

## 3. 端口冲突导致工具静默失败

**TL;DR**:工具声明的端口被占用时,子进程会 crash(被 manager 反复拉起),页面打不开且原因不明显。

- 问题:`/tool/<id>` 超时/502
- 根因:registry 未在启动时校验端口占用
- 解决:启动时对工具段 8100~8199 做端口占用预检;冲突工具标记 `error` 并跳过 spawn,首页红点提示
- 预防:registry 校验是必经环节,不能只靠运行时容错

## 4. NAS 容器写卷 EACCES 权限错

**TL;DR**:容器内 root 写挂载卷,在宿主 File Station 里出现权限错/文件属主异常。

- 问题:工具写 `data/` 报 `EACCES: permission denied`,或写出的文件宿主删不掉
- 根因:容器 root(UID 0)与宿主用户 UID 不匹配;DSM 的 POSIX ACL 较严
- 解决:compose 设 `PUID/PGID`(宿主 `id` 查得,通常 1026/100);挂载目录 `chown` 对应 UID;**先建目录再起容器**
- 预防:所有 NAS 部署模板默认带 PUID/PGID + TZ

## 5. 微信读书 API Key 失效(长期有效但可能重置)

**TL;DR**:Agent 网关 Key(`wrk-`)长期有效,但官方重置后工具报鉴权错,需在配置页更新。

- 问题:购书工作台报"未配置 API Key"或 401
- 根因:Key 绑定账号,官方可能重置或账号变更
- 解决:Key 存挂载卷配置(`data/config.json`);配置页提供测试按钮,报错时提示去 `weread.qq.com/r/weread-skills` 重新获取
- 预防:工具内部对鉴权错误做明确提示,不吞错
